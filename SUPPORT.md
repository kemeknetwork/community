# Getting help

Pick the channel that matches what you need. Using the right one is the fastest
path to an answer.

## Public — use Discussions

**Best for:** how-to questions, "is this a bug?", feature ideas, sharing what
you built, general conversation about KeMeK products.

→ [Q&A](https://github.com/kemeknetwork/community/discussions/categories/q-a)
for questions.
→ [Ideas](https://github.com/kemeknetwork/community/discussions/categories/ideas)
for suggestions.

Public threads help the next person with the same question, so prefer them
whenever the subject isn't sensitive. [CONTRIBUTING.md](./CONTRIBUTING.md) has
guidance on writing a post that gets answered.

## Mistakes in these documents — use Issues

**Best for:** a dead link, a typo, information that has gone stale, or routing
that sent you somewhere useless.

→ [Open an issue](https://github.com/kemeknetwork/community/issues).

That tracker covers this repository's own files and nothing else. It is not a
product issue tracker: a problem with a KeMeK tool or site is a discussion, not
an issue, because product source lives in private repositories and an issue
here cannot reach it.

## Private — email

Some things do not belong in public. Use email when your question involves:

- **Account, billing, domains, hosting, or SSL** — anything tied to a specific
  customer account, an invoice, or a contract.
- **Personal data** — yours or someone else's.
- **Credentials, tokens, or configuration** that would expose a system.
- **Commercial enquiries** — proposals, scoping, partnership.

**Where to write:**

| Topic | Address |
| --- | --- |
| Hosting, domains, email, SSL, billing | [support@kemek.net](mailto:support@kemek.net) |
| Consultancy, proposals, partnerships | [hello@kemek.com](mailto:hello@kemek.com) |
| Code of Conduct reports | [conduct@kemek.com](mailto:conduct@kemek.com) |

## Security vulnerabilities

**Never** report a vulnerability in a public discussion. See
[SECURITY.md](./SECURITY.md) for the disclosure process.

## What we ask in return

Whichever channel you use: say what you expected, what happened instead, and
what you already tried. That single paragraph saves a round-trip and usually
gets you an answer the same day rather than the same week.
